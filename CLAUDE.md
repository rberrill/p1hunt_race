# P1 Hunt Race: working notes for Claude

A free browser tool that picks a giveaway winner by running an F1-style race on screen. A breaker loads a list of entrants, the audience watches the cars race, and one entrant wins with the full finishing order recorded. Same entrants, duration and seed always give the same result, so a contested race is re-run on stream in seconds. It is promotion for P1Hunt. Public repo `rberrill/p1hunt_race` (GPL-3.0); Pages will serve https://rberrill.github.io/p1hunt_race/ once there is a release. The product definition (2026-11-01) and the eleven wireframes are kept locally in `archive/`; the decisions they settled are the list below.

- **Who uses it:** a breaker on a Whatnot stream, sharing a browser window from a **second device**: a computer running OBS, or a second phone in portrait. Never the streaming phone. The operator's screen is the audience's screen, so every phase has to look good on stream.
- **What they need, in order:** viewers can read and trust the entrant list; the race reads clearly on a phone-sized stream; the winner is unmistakable; re-running a contested race takes seconds.
- **Versions:** this is a fresh project. It starts at 0.1.0 and aims at a 1.0.0 public release; nothing from the v2 folder (`../archived/p1hunt-race/`, reference only) was ever released.

## How we work

1. **Agree before building.** When Rich describes a feature or a batch of changes, reply with a proposal: what changes, how, open questions and gaps; its new UAT cases, the connected catalog cases it could affect, and whether a full UAT run is triggered (the `uat` skill). Don't edit code until he agrees the full set. Small, clear bug reports with steps can be fixed straight away (Claude's habit, not a rule Rich set).
2. **Write for the reviewer:** whole-word names, one statement per line, lines of 100 characters at most, a comment on every function. The detail is in `.claude/rules/code-style.md` (it loads with any code file).
3. **Build, then verify yourself** with the `verify` skill. Report measured results, not assumptions.
4. **UAT** (the `uat` skill): a catalog of every case, the release smoke test, and a script per version, all local. Rich runs the version script on the dev build (desktop on `localhost`, iPhone over the LAN), with a fresh dev number for every changed build. Section 7 is a real-use run: a race captured through OBS and through a second phone.
5. **Release only on Rich's go-ahead.** He runs `/release X.Y.Z`, which tags `main` and moves `release` (the live site) to the tag.
6. **Record as you go:** user-visible changes in `CHANGELOG.md` under `## [X.Y.0] - Unreleased`; decisions, and files changed in the background, in `../../decision-log.md` (dated, newest first, with the *why*); the "Waiting on" line in `CLAUDE.local.md`.

**Rich's preferences:** direct feedback, push back when something is wrong; simplicity over features; no messages a user can't act on; nothing covers the stage except the timing tower and a temporary flyout the breaker opened (the tower: Rich, 2026-11-01).

**Brand:** matte black, white, and P1Hunt red (`#e5322d`), retro motorsport, no gradients. Inspired by F1, never its trademarks: no F1, FIA, team or driver logos or marks in the app or the docs.

## Hard constraints (still binding)

- **Plain static files:** no build step, no packages, no frameworks, zero runtime dependencies, nothing loaded from another site. ES modules (`<script type="module">`, `import` / `export`) on relative paths, with `?v=<appVersion>` on every asset link and static import. Must work from `localhost` and from a Pages subfolder. (`file://` is not supported: Rich dropped that constraint for ES modules, 2026-11-01.) The `package.json` only tells Node the files are modules; it declares no dependencies (Claude's call).
- Everything stays in the browser: no backend, no uploads, no analytics.
- **Deterministic engine:** `js/engine.js` is pure. The result is a function of entrants, seed and duration only; it never reads the clock, the frame rate, `Math.random` or the DOM. The rules in `.claude/rules/engine.md` load when you touch it.
- **Touch first:** everything works by touch alone, with ≥ 44 px targets and safe-area padding. Keyboard shortcuts are extras.
- Every tunable lives in `CONFIG` (`js/config.js`), overridable from the URL (numbers and on/off only, within `CONFIG_LIMITS`).
- **Security:** never build HTML from strings; keep the strict CSP; untrusted input (links, CSV files, localStorage) goes through one sanitizer; `tests/selftest.js` enforces what it can. Before checking out an outside contributor's branch, read its diff to `.claude/` and `tests/`: the hooks run that code without asking.
- **Public repo:** nothing personal or machine-specific in committed files (addresses, local paths, names beyond Rich's). That goes in `CLAUDE.local.md`. Selftest checks for addresses and paths.
- Keep the internal names `storageKey: 'p1hunt.race.v1'` and `window.__race` (Claude's names); renaming them breaks saved sessions and the tests.

## Settled product decisions (don't relitigate without Rich)

All from the product definition, decided with Rich on 2026-11-01 unless marked otherwise.

- **Name:** P1 Hunt Race. "Duck Race" is retired. No Shopify embed; it lives on its own page.
- **Three full-screen phases in a loop:** Control → Race → Winner → Control, with the list and seed already confirmed. No sidebar-plus-stage layout.
- **Control** holds the entrant list, the seed and the duration on one page viewers can read; it doubles as the confirmation page after a race. One button, Start race, hands the viewport to the stage.
- **Entrants:** typed one per line, or imported from a CSV using the template the app offers for download. 2 to 100; breaks of 75 are routine and a big field reading as a pack is accepted.
- **CSV template:** `name` required, `spots` optional (blank = 1). Spots add up across lines: `Rich,3` and three lines of `Rich` both give Rich three entrants.
- **Duplicate names:** the entrant is the plain name; on display (car labels, grid, finish order) a repeated name gets `-1`, `-2`, `-3`. Usernames are often alphanumeric, so a suffix must never read as part of the name.
- **Seed:** the fairness story, kept from v2 (text field, New seed, Unlocked / Locked). The engine behind it is rebuilt.
- **Duration:** 10 to 120 s. It is part of the deterministic result, not only the animation length; the default is open until the engine design.
- **Race format:** a live simulated race, not a choreographed reveal. A vertical perspective road, cars seen from behind, turns at seed-and-duration-set intervals; cars brake into a turn and accelerate out; seeded speed checkpoints along each segment decide who gains and loses. Deterministic because the seed and checkpoints are fixed, not because the result is decided up front. Direction set; the engine session designs it from the definition's three starting questions (fixed timestep, approximate duration, the tail of the field).
- **Race controls** work like a social video player: an always-on bar at the bottom with Pause/Play and Reset; **the bar's Pause and a tap or click on the stage both pause the race at once** and dims it with the options large: Play, Reset race, Start over (Rich, 2026-11-01; the overlay never runs the race on behind it and has no timer; a tap outside the buttons leaves the race paused). **Start over from the race keeps the seed and its lock state** and returns to Control with the list, so a race left before the finish runs identically from Start race (Rich, 2026-11-01: leaving a race can never change its result). **A timing tower over the left of the stage, broadcast style** (Rich, 2026-11-01, replacing the order strip above the stage and the leader chip): the rows flow to the bottom of the stage and "+ n more" is the last line only when they run out of room (Rich, 2026-11-01: a "+ n more" with space under it looked out of place; `towerMaxRows` is a link-only cap, 100 by default); **the first three rows full width, the rest small: the same information at about two thirds the size, the full name never cut, the gap beside it** (Rich, 2026-11-01: smaller, never less; two thirds rather than half is Claude's call, half being unreadable); each row a place, a swatch in the car's color, the name and the gap to the leader, a rough translation of distance to time (the distance divided by the trailing car's current speed; Rich asked for the rough version), exact once both have crossed; the winner's row shows its time. **The tower refreshes every `towerRefreshMs` (1.5 s), like a TV timing graphic, not every frame, and a row flashes green for a place gained, red for one lost** (Rich, 2026-11-01). **A row is a car, and slides to its new slot** (Rich, 2026-11-02): one row per car, placed at the slot of its place from the row heights the stylesheet declares, sliding over 400 ms and growing or shrinking as it crosses the top three; no slide under reduced motion; the reveal leaves the slots above the revealed rows empty rather than dashed (Claude's call). Taps pass through it. **A hidden tab pauses the race** (Rich, 2026-11-01): race time stops while the tab is hidden or the device sleeps and resumes from the same tick, like a media player losing focus; missed time is never caught up.
- **Top-three tower names are never cut** (Rich, 2026-11-02, from the phone with the 30-handle list, where "SlipstreamSteve" ended in an ellipsis): a major row's name shrinks to fit beside its gap, measured like the Winner hero, from the major size down to the minor rows' size; only a name that won't fit even there is cut with an ellipsis, the last resort (Claude's call; on the phone that is a name over about 22 characters, measured). The name snaps rather than eases as its row crosses the top three, because the fit's probe needs the span free of transitions (Claude's call).
- **Winner:** its own screen: the winner large, the full finishing order, CSV and JSON export, the race record (kept in localStorage). Re-run keeps entrants, duration and seed and plays the identical race; Start over returns to Control with the list kept and a fresh seed (the race overlay's Start over keeps the seed; see Race controls). **The hero shows the winner's plain name**, without the `-1`, `-2` suffix; the finish order keeps it (Rich, 2026-11-01). **The hero name never wraps** (Rich, 2026-11-01): it is measured and sized to fit the width on one line, down to 10 px.
- **Branding on the stage:** P1Hunt only. No breaker name or logo field; a branded version is a paid custom later.
- **Session restore** follows the Finisher: every change to the list and setup is saved to localStorage as it is made; on reload the app asks Resume / Start over, never restores silently.
- **Breakpoints:** phone up to 760 px (`max-width: 760px`, the Finisher's line), mid 761 to 1100, desktop above 1100. Control stacks on the phone and puts entrants beside a setup column above it; Race and Winner use the full viewport at every width.
- **Accessibility:** an ARIA live region and a `prefers-reduced-motion` race mode that produces the same result (kept from v2; the mode is designed with the new format).
- **Versioning:** SemVer by user-visible change, from 0.1.0 toward 1.0.0. Process and tooling changes don't bump the major.
- **Race time** (engine session, 2026-11-01): 60 ticks per second; a frame only decides how many ticks run. Seeded by xoshiro128** from FNV-1a of the seed text, one stream per purpose; the engine uses only exactly rounded arithmetic (no `sin`, `exp`, `pow`, `log`), so the finish is identical on every device (Claude's technique for the definition's requirement); a reference race's fingerprint in `selfTest()` proves it on each device. Results are reproducible within an app version; the record carries the version, and **Re-run of a record from another version warns and runs** (Rich, 2026-11-01): the saved order stays in the record and the exports. **The seed's case is folded** (Rich, 2026-11-01): `k7mx-4qzd` is the same race as `K7MX-4QZD`, shown as typed. **New seed makes `XXXX-XXXX`** from an alphabet without `0 O 1 I` (Rich, 2026-11-01); any typed text is also a seed.
- **The track comes from the seed and the duration** (Rich, 2026-11-01): 1.5 to 2 turns per 10 s of duration (2 to 3 until 2026-11-02, when Rich asked for longer straights: the long ones are now five times a short one, after three, and the sweepers run to 2 units), a mix of short straights and 1 to 3 long ones, each corner's direction and sharpness seeded, so every seed-and-list pair is its own race, Pole Position style. The straights scale so a nominal car crosses at the duration; the winner lands a little early (measured 95–99.5 % of the duration from 24 cars up) and the last car a little late (up to 105 %). **Default duration 30 s.**
- **Every car has the same base pace, always** (Rich, 2026-11-01). Nothing is fixed before the start; only the seeded checkpoints along the road (launch, straights, corners) set a car apart. Not a tunable. **The start is one line** (Rich, 2026-11-01): every car at distance 0 with a seeded lane; no grid rows, so no one starts behind.
- **The tail: hold the line** (Rich, 2026-11-01, over Claude's cut-with-grace lean). Every car crosses; every place is a real crossing with a time; the Winner screen comes after the last car.
- **Result-affecting tunables are link-overridable** within `CONFIG_LIMITS`, and every override in effect goes into the race record and both exports, so a tweaked link can't pose as a stock race (Claude's call, put to Rich 2026-11-01 without objection). `ticksPerSecond` is not overridable.
- **Reduced motion is a shell drawing policy**, not an engine mode: the shell runs the race with `runToFinish` and reveals the finish without motion; the engine's result is the same by construction (Claude's call).
- **The 0.1 interface** (Rich's answers to the interface proposal, 2026-11-01): **stage assets are code-drawn vectors** on the canvas, no image files; the Finisher's icon set is the app icon for 0.1 and Rich's official logo may replace it later. **The camera follows the leader, then parks at the finish** while the rest cross. **Labels on cars drawn wide enough** (`labelMinWidthPx`) **and always on the top three** of the live order (Rich, 2026-11-01), **each directly over its car and never lifted into a stack** (Rich, 2026-11-02: the top three always, even where two overlap, with the car ahead painted whole; the rest only where the label is free; the first cut lifted a covered top-three label above the other); **pack labels hold their spot and wait for a clear one** (Rich, 2026-11-02: they popped in and out too fast to read): a name once shown keeps its spot, yielding only to a top-three name or an older one, and a new name is drawn only after its spot has been clear for `labelShowDelayMs` (300 ms); a name leaving the top three keeps its spot as an established one. Measured on the phone width with 40 names over 6 s: label appearances 172 → 29, median label life 117 ms → 483 ms. **Label treatment** (Rich, 2026-11-02, Claude's pick from six mockups in `archive/label-options.html`, after Rich asked for alpha so the cars show through): the top three on a translucent box (55 %) with its place, 1 to 3, at the left in the tower's place colours (Rich, 2026-11-02, over the colour edge first built), the pack as bold haloed text with no box; a box survives stream compression for the names that matter and the pack recedes; where two top-three boxes overlap the car ahead's is painted opaque, since two translucent boxes read as one garbled name (Claude's call, seen on dev.38); the haloed text's legibility through OBS is judged in section 7; the timing tower carries the top places. **A three-light countdown** (`startCountdownSec`), drawn just above the cars on the start line, centred on the road there (nothing else is on the stage then; the rows-beside-the-lights clearance of 2026-11-01 went with the hold below); elapsed runs from lights out. **The tower and the names on the cars are held until the first refresh after lights out** (Rich, 2026-11-02, on purpose: "it gives some time for a little separation and to get off the line"): through the countdown and the first `towerRefreshMs` of race time the stage is the road, the cars and the lights alone; then the tower appears already in race order, without a slide or a flash, and the names with it; a pause in the countdown holds them too, and Reset holds them again. Reduced motion has no countdown; its tower is the reveal. **The road is drawn `roadViewUnits` ahead and fades into the verge at a vanishing point, and a strip's bend is integrated in fine steps, so a far turn grows in instead of popping** (Rich, 2026-11-01: the far road snaked and jumped; the whole track used to be drawn into a 30 px band). **Speed is tuned on the stage, not in the engine** (Rich, 2026-11-02: "F1 is fast"; Claude's analysis: what reads as speed is units per second over units in view plus the texture streaming past, and a higher top speed only lengthens the straights in units because the duration fixes the seconds): `roadViewUnits` 7 and `viewDepthUnits` 4 (12 and 6 before), kerbs every `kerbUnits` (0.15) and dashes every `dashUnits` (0.3), and **braking boards** (`boardCount` 3, `boardUnits` 1 apart) on the outside verge before every corner, three, two and one red bars toward it, the trackside parallax the stage lacked and a mark for the braking zone; all link tunables, to settle on the phone; the engine's straights and top speed are the next lever if the straights still feel short. **Reset parks the cars on the line, paused**, with Play showing. **Reduced motion is a still frame with the order filling from last to first** over `revealSec`, then the Winner screen. **Clear asks in a confirmation card** (Clear / Keep). **The HUD shows the full seed, small, beside the P1 mark** (Rich, 2026-11-01: it looked out of place next to the elapsed time).
- **The HUD clock is the session time, counting down from the duration** (Rich, 2026-11-02, reversing the definition's elapsed-not-remaining, which feared a clock at zero with cars still running): the full duration through the lights, counting down from lights out, and once past zero held at 0:00.0 while the tail crosses, like the chequered flag at the end of a timed session; each car's finish time still counts up and is what the tower's winner row, the Winner screen and the exports report. Reduced motion's reveal shows 0:00.0 throughout (Claude's call; the winner's time is in its tower row).
- **Speed contrast: preset C** (Rich, 2026-11-01, after Claude measured three presets), then softened the same day once the top speed was in ("the slow-down in the turns is a little too aggressive"): acceleration 1.0/s (braking was 4/s until the corner model, below), launch ±15 %, straight checkpoints ±12 %, corner factor ±15 %. (Its apex range and its braking and exit zones were replaced by the corner model of 2026-11-02, below.) **The fingerprint match across devices is a release smoke-test item** (SP2 against SD2), not something to report after every change (Rich, 2026-11-01).
- **A top speed on the straights** (Rich, 2026-11-01): `straightTopSpeed` 1.5 × cruise (1.8 was tried on the phone and felt see-saw into and out of the corners), reached at 1.0/s and braked from at 4/s, so a straight is where speed builds and the straights between 2–3 turns in 10 s are long enough to read (about twice their earlier length). The straight scale is bisected to fit the duration (Claude's call).
- **Brake on the straight, hold the corner, accelerate from where the road straightens** (Rich, 2026-11-02; the earlier model slowed inside the drawn bend, a V-shaped dip at the apex). A car brakes at `brakingPerSec` (2/s; 4/s read too short on the stage, Rich, 2026-11-02, so the braking zone is about half a second and half a unit from top speed) as late as that rate allows (v² = u² + 2·a·s, multiplication only) to reach the corner's speed where the bend starts, holds it to the apex, and **opens the throttle at the apex** (Rich, 2026-11-02: "that's how it should run"; the first cut held to the bend's end), building out while the road straightens; the bend is drawn over the corner alone, with no lead-in. **Corners differ by sharpness** (Rich, 2026-11-02): one seeded draw per corner sets both its held speed (`apexSpeedMax` 1.5 of cruise for a sweeper, the straight's top speed, so the widest corners are flat out with no lift: Rich, 2026-11-02, "100 % of max"; down to `apexSpeedMin` 0.50 for a hairpin: the floor went 0.40 → 0.50 → 0.60 → 0.70 through the day as the stage read too slow, then back to 0.50 once the sweepers were flat out, so the sharpest turns slow the cars down a lot against them (Rich, 2026-11-02); a corner never asks more of a car than its own straight pace, Claude's cap) and its length (`cornerUnitsMax` 2 units down to `cornerUnitsMin` 0.5, with `cornerLengthJitter` ±15 %; the ceiling was 1.3 until the longer straights of 2026-11-02); coupling the two keeps every corner between about 1 and 1.5 s and is Claude's call. The ranges are a first pass, to tune on the stage by link (`?brakingPerSec=1.5`, `?apexSpeedMin=…`). Measured: the 75-car tail at 30 s is 2.7 s mean, 3.5 s max over eight seeds (1.9 and 2.4 with the shorter straights; 2.5 and 2.9 before the model).
- **Corner exits** (Rich, 2026-11-02): per car and corner a seeded exit quality on a bell, most near average and a few great or poor, scales the car's acceleration from the apex (`exitSpread` 0.6: a great exit builds at 1.6× the base rate, a poor one at 0.4×) until it is back at its straight pace; a flat-out sweeper has no exit to speak of, a slow corner a long one. Three uniform draws averaged, centred and squared with the sign kept (Claude's shape: sums and products only, so it rounds the same everywhere). The nominal car is untouched, so the duration promise holds. **Measured honestly** (eight seeds, 30 s): the exits alone add about one lead change per race (24 cars 12.0 → 12.5 leader changes, 75 cars 16.1 → 17.5), while the longer straights of the same build take more away (both together: 10.5 and 12.1), because the three checkpoints per straight were per straight whatever its length, so a 10-unit straight ran most of its length with no new draw; fixed the same day by the per-unit count below.
- **Checkpoints per unit of straight** (Rich, 2026-11-02, on that measurement): `checkpointsPerUnit` (1.5) times the straight's length, rounded, at least one, replaces the fixed count per straight; a short straight of about two units keeps about three, a ten-unit straight gets fifteen, so the order keeps moving down the long straights. Measured (eight seeds, 30 s, leader changes / top-three set changes): 24 cars 13.4 / 37.4 and 75 cars 17.8 / 45.3, above the dev.30 baseline (12.0 / 29.4 and 16.1 / 38.1); 2 and 3 per unit were no clearer win on eight seeds, and 1.5 is the smallest value that beat the baseline at both sizes (Claude's pick). More checkpoints average out, so the 75-car tail fell to 1.7 s mean, 2.2 s max.
- **A seeded pace per straight** (Rich, 2026-11-02, on the field the per-unit checkpoints bunched: the median car sat 20–30 % closer to the leader than before, at 30 and 60 s, because independent draws average out over a straight): per car and straight one draw, `straightSpread` (0.06), under every checkpoint on that straight, so a good or bad straight lasts the straight while the checkpoints still shuffle the order along it. Spread and lead changes pull against each other in this model (persistent differences spread the field, fast noise churns it); 0.06 gives the earlier spread back (median / last car behind the leader mid-race at 30 s: 24 cars 0.88 / 1.85 units, 75 cars 1.03 / 2.17; at 60 s 1.31 / 2.75 and 1.62 / 3.50) with leader changes 9.5 and 16.4 per race (24 and 75 cars, 30 s). A link tunable, to settle on the stage against `checkpointSpread` (`?straightSpread=0.08`): no setting beats both metrics at once, so the dial is a judgment by eye.
- Claude's interface calls (2026-11-01, open to objection): a Tuned link chip in every header while link settings are in effect; a frame gap over `maxFrameGapMs` is dropped from the race clock (a stalled device never bursts ticks); the other-version warning sits on Control's back line after Resume, where Start race is the re-run (the Winner screen's Re-run only follows a race just run by this version); Copy result is hidden, not disabled, without a clipboard; exports are named `p1hunt-race-<seed>-<yyyymmdd-hhmm>`.
- **The car is Option B of the car mockup, flat shading** (Rich, 2026-11-02, from three options drawn in `archive/car-options.html`): wide low pods, an engine cover that hides all but the top of the helmet, a two-element wing low over the cover, tyres with a tread band, wishbones and a diffuser; shade bands, never gradients. **A second color per dozen cars** (white, dark, yellow, blue, red after the single-tone first dozen) on the pod band, the cover band, the flap and the endplates, so 75 cars get 72 liveries; **the tower's swatch stays the main color** (Rich, 2026-11-02). The proportions are `CAR_SHAPE` in `stage.js`.

## Follow-ups before the next version

Open points from the 0.1 design-and-build pass, each still to be decided with Rich before any version after 0.1 starts (Rich, 2026-11-02: listed here as the gate). Remove a line when it is settled, and log the call in the decision-log.

- **A bunched field flashes many tower rows at once** on a refresh, when a few cars trade several places in 1.5 s. Decide: flash only the top rows, flash less often, or accept it.
- **`towerMaxRows`** is kept as a link-only cap at 100 (Claude's call); the rows already flow to the bottom. Decide: keep it or remove it.
- **33 small rows on a phone** with a 75-car field is dense. Decide against the OBS and second-phone captures in section 7 of UAT-0.1 before changing anything.
- **The dark accent and the dark-red car** (from the car pass, 2026-11-02): the dark grey accent on a dozen's pods and endplates, and the red accent on the dark-red twelfth color (car 60 in a 75-car field), are the two low-contrast liveries. Judge both on the section 7 captures; if either vanishes, change the accent, not the car.
- **The 75-car frame rate on the phone** with the heavier car (about three times the draw calls of the dev.19 car) is only judged by eye (P3.17); the hook can't measure the GPU side. If the pack stutters, the first lever is `CAR_DETAIL_MIN_PX` in `stage.js`.
- **The test hook's `frameAt` after `reset()`** draws the road without cars once the clock is stepped on from zero (seen on 2026-11-02 while verifying dev.20; a single `frameAt` straight after `startRace` draws them). **A real-time race in the browser pane can sit at `tick` 0 for good** (2026-11-02, dev.21 to dev.24): while the Claude window is hidden or covered the pane gets one or two animation frames a second, every gap is over `maxFrameGapMs` and is dropped from the race clock, so it never advances. Not the app; drive those checks with `frameAt` (it also steps the reduced-motion reveal), `pause()` first so the loop's next throttled frame doesn't repaint the stalled clock over the stepped frame, and screenshot only with the pane fronted. The camera's follow uses the wall-clock frame delta, so stepped frames leave it near the start.
